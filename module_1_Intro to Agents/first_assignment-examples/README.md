# Meeting Notes Course: Idea to Shipped Product (Local First)

A worked example of the Module 1 workflow: take a one-line problem, turn it into a PRD, hand the PRD to an AI coding agent, and end up with a running local app, with no deployment required.

The app built here is **Recapp**, a local-first tool for capturing meeting decisions and action items.

## The workflow, step by step

| Step | File / Folder | What happens |
|------|---------------|---------------|
| 1. Module context | [`CLAUDE.md`](CLAUDE.md) | Standing instructions for the coding agent: what this module is, the folder map, and how to work with you |
| 2. Generate a PRD | [`prd-generator/prd-generator.html`](prd-generator/prd-generator.html) | The PRD Builder. Fill in 4 fields, watch an 8-section PRD stream in, then save it to a folder |
| 3. The PRD | [`prd-generator/recapp/prd.md`](prd-generator/recapp/prd.md) | The actual PRD that Recapp was built from, generated by the tool above |
| 4. Project context | [`recapp/CLAUDE.md`](recapp/CLAUDE.md) | Tells the coding agent who you are, what you are building, and the scope guardrails from the PRD |
| 5. Install skills | [`.claude/skills/`](.claude/skills/) | `/prd-generator` and `/user-story-writer` are installed as Claude Code skills, available anywhere in this module |
| 6. Build the MVP | [`recapp/src/`](recapp/src/) | Ask Claude Code to build against the PRD. This repo already has the result as a reference |
| 7. Run locally | see below | `npm run dev`, no deployment needed |
| 8. Inspect, iterate | (no file) | Open the app, try it, then ask the coding agent for changes |

## API keys: never commit them

The PRD Builder needs an Anthropic API key. Two ways to hold one:

- **In the browser tool itself:** paste it into the "Anthropic API Key" field. It is saved only to that browser's `localStorage` and is never written to a file.
- **For local scripts** (e.g. `recapp/scripts/test-anthropic-key.mjs`): copy `recapp/.env.example` to `recapp/.env.local` and put your key there. `.env.local` is already covered by `.gitignore`, so it will never be committed. Never paste a real key into a `.md` file, a chat, or any source file.

Check a key works without printing it:

```bash
cd recapp && npm run test:key
```

If a key is ever exposed, rotate it in the [Anthropic Console](https://console.anthropic.com/settings/keys).

## 1. Use the PRD Builder

Two columns: fill in the form on the left, watch the PRD stream in on the right.

```bash
cd prd-generator
python3 server.py
```

Then open **http://localhost:4321/prd-generator.html** in **Chrome or Edge**.

- Paste your API key, then fill in feature name, problem, target users, and constraints
- Click **Generate PRD**. It streams an 8-section PRD live from Claude
- **Save PRD to Folder** opens your browser's folder picker. Choose any folder, approve the "Allow this site to edit files?" prompt, and it creates a subfolder named after your app containing `prd.md`, for example `recapp/prd.md`
- **Download as .md** is the usual browser download and works in any browser

After saving, a **Start Building** panel appears with a ready-to-paste prompt for Claude Code, plus two follow-up prompts.

Chrome and Edge are required for the folder picker. In Safari and Firefox, **Save PRD to Folder** falls back to writing into `prd-generator/` through the local server, and tells you it did so.

**Two different "PRD generator" things exist in this course, so do not mix them up:**

| | `prd-generator/prd-generator.html` | `/prd-generator` (Claude Code skill) |
|--|--|--|
| What it is | A browser page that calls the Anthropic API directly from JS | A skill file (`.claude/skills/prd-generator/SKILL.md`) that Claude Code reads and follows |
| Where you run it | Any browser, even with no code editor open | Inside a `claude` session, anywhere in this module |
| Needs an API key? | Yes, pasted into the page | No, it uses whatever Claude Code session you are already in |
| Why it exists | To show what PRD generation looks like end to end, including the raw API call | To mirror the real course workflow: install a skill, run `/prd-generator`, read its `SKILL.md` to see how it works |

## 2. Recapp

[`recapp/`](recapp/) is a Next.js MVP built directly from [`prd-generator/recapp/prd.md`](prd-generator/recapp/prd.md). It covers all 8 must-have stories in that PRD:

- Create a recap for a meeting, with a required name
- Add lines, and mark any line as a **note**, a **decision**, or an **action item**
- Assign an **owner** to an action item. Actions with no owner are flagged as unassigned
- Group recaps under a recurring **meeting series**, e.g. "Weekly Standup"
- **Search** across every recap, with results showing both the recap and the matching line
- Everything autosaves to `localStorage`. No account, no login, no backend

Beyond the must-haves it also includes: marking action items done, deleting a recap, a cross-meeting **open action items** view, and a **JSON backup export**. The export is deliberate: the PRD names permanent data loss as its top risk, since everything lives in browser storage with no recovery.

### Run it locally

```bash
cd recapp
npm install
npm run dev
```

Then open **http://localhost:3000**.

There is nothing to deploy for this exercise. Running it locally satisfies the "local first" requirement in the PRD.

### How the data is shaped, and why

A recap is an ordered list of **entries**, not a single block of text. The PRD requires marking an individual line as a decision, or as an action item with an owner, which a single text field cannot express without fragile parsing. See [`recapp/src/lib/types.ts`](recapp/src/lib/types.ts).

## 3. Iterate with the coding agent

Open Claude Code inside `recapp/`, which already has a `CLAUDE.md` with project context and the PRD's scope guardrails. Try prompts like:

- "Let me export a single recap as markdown so I can paste it into an email"
- "Add tags to recaps so I can organize by theme"
- "Add a keyboard-shortcut quick-entry mode for taking notes during a live meeting"

Each maps to a Should-have or Nice-to-have in the PRD, which makes them good practice at going from PRD to prompt to shipped change.

## Why this is "local first"

- No Vercel, no Fly.io, no environment variables, no signup needed to run Recapp
- Data lives in the browser (`localStorage`), which is good enough to learn the full idea-to-product loop without deployment friction
- The PRD Builder is the only piece that talks to a network, and only because generating a PRD needs Claude
