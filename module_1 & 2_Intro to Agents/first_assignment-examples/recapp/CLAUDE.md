# Recapp: Project Context

## What this is

Recapp is a local-first app for capturing meeting decisions and action items. It was built directly from the PRD generated by the PRD Builder, which lives at `../prd-generator/recapp/prd.md`. Read that PRD before making changes: it is the source of truth for scope.

This is the Module 1 course exercise: problem statement, PRD, CLAUDE.md, build the MVP with an AI coding agent, run locally, iterate.

## Skills available in this repo

These live one level up, in the course folder's `.claude/skills/`, so they work from anywhere in the module.

- `/prd-generator` ([`../.claude/skills/prd-generator/SKILL.md`](../.claude/skills/prd-generator/SKILL.md)) generates a structured PRD from a feature brief

## Who I am / what I'm building

- I am a non-engineer or PM learning to ship with Claude Code, not a professional developer.
- I want a working app I can run on my own machine, with no deployment and no login. It should stay local-first by default: the one exception is the transcript-extraction API route, added deliberately, not a green light for more backend calls without asking.

## Stack

- Next.js (App Router) with TypeScript and Tailwind CSS
- No database. Almost all data is persisted in the browser via `localStorage`
- One backend exception: `src/app/api/extract-actions/route.ts` calls the Anthropic API server-side to turn a pasted or uploaded meeting transcript into a suggested title, series, decisions, and action items. This needs `ANTHROPIC_API_KEY` in `.env.local` to work. It is the only network call the app makes; the transcript text is sent for that one request and is never stored server-side.
- `src/lib/anthropic.mjs` decides which endpoint and model that route calls, from `ANTHROPIC_BASE_URL` and `ANTHROPIC_DEFAULT_SONNET_MODEL`. Both fall back to `https://api.anthropic.com` and `claude-sonnet-5`, so the app works with no extra settings. Set them in `.env.local` to reach an LLM proxy instead. See `.env.example` for the three names. The file is `.mjs` rather than `.ts` because `scripts/` imports it and `node` runs those scripts with no build step. Run `npm run test:config` to check the resolver, and `npm run test:key` to make one real call.

## Data model, and why it is shaped this way

A recap is an ordered list of **entries**, not one free-text blob. The PRD requires marking an individual line as a decision, or as an action item with an owner, which a single text field cannot express without fragile parsing.

- `src/lib/types.ts` holds `Recap` and `Entry`. An `Entry` has a `type` of `note`, `decision`, or `action`, plus `owner` and `done` for actions.
- `seriesName` is a plain string on the recap rather than a separate entity, so grouping recurring meetings needs no extra navigation layer.

## Conventions

- All reads and writes to `localStorage` go through `src/lib/storage.ts`, never directly from components
- Search and cross-meeting queries live in `src/lib/search.ts`
- UI is split into `src/components/RecapSidebar.tsx` (list, search, create), `src/components/RecapEditor.tsx` (one recap), and `src/components/EntryRow.tsx` (one line), composed in `src/app/page.tsx`
- Keep it simple. This is an MVP for a course, not a production app. Prefer small readable client components over new abstractions, state managers, or backend infrastructure.

## Scope guardrails from the PRD

The PRD explicitly rules these out, so do not add them unless I ask:
no calendar or video tool integration, no real-time multi-user editing, no accounts or cloud sync, no notifications or reminders, no analytics dashboards.

One deliberate exception to the PRD as written: it also rules out audio recording, transcription, and AI-generated summaries, all in the name of staying fully local. We added transcript-to-action-items extraction anyway (see Stack above), which sends transcript text to Anthropic's API. That was an explicit ask, not scope creep, but it does mean the app is no longer 100% local end to end. Treat this as the one accepted deviation, not a precedent for adding more AI features without asking first.
